# 냥스타 키친 — "진짜 게임처럼" 만들기 변경사항

기존에는 백엔드 로직(경제·손님 FSM·사냥·방치수익·세계수 진행·저장)은 잘 짜여 있었지만,
**플레이 화면이 사실상 없었습니다.** 유일한 조작 수단이 디버그 버튼(`DebugTester`의 IMGUI)이었고,
식당은 컬러 블록 + 스프라이트 몇 개, 사냥은 시각적 미니게임 없이 버튼만 누르는 구조였습니다.
게다가 프로젝트가 **새 Input System 전용**이라 일반 UI 캔버스를 올려도 클릭이 먹지 않았습니다.

이번 작업으로 **실제로 손으로 즐기는 타이쿤 게임 플레이 레이어**를 코드로 새로 구축했습니다.
백엔드 매니저와 기존 테스트(`EconomyMathTests`), 수치 로직(`UpgradeData`)은 **건드리지 않았습니다.**

---

## ▶ 실행 방법

두 가지 중 아무거나:

1. **(권장) 셋업 다시 실행** — 상단 메뉴 `Nyangsta > Setup > Generate Everything` 클릭 →
   `Assets/_Project/Scenes/Bootstrap.unity` 열고 **Play**.
2. **그냥 Play** — 기존 `Bootstrap` 씬에서 바로 Play 해도 됩니다.
   런타임 부트스트랩(`GameUIBootstrap`)이 매니저를 감지해 새 게임 UI를 자동으로 띄우고,
   남아 있던 디버그 오버레이는 자동으로 숨깁니다.

> 세로/가로 화면 모두 자동 대응됩니다. (Game 뷰 비율을 바꿔도 레이아웃이 맞춰집니다.)

## 🎮 무엇이 생겼나

- **상단 HUD** — 골드/보석/세계수 정수, 현재 지역·세계수 레벨, 사운드 토글. 숫자는 부드럽게 롤링.
- **하단 탭 네비** — 식당 · 사냥 · 업그레이드 · 모험 · 직원. 탭마다 전용 화면.
- **인터랙티브 사냥 미니게임** *(핵심)* — "사냥 시작" → 지역 배경 위로 재료가 통통 튀어나오면
  **직접 탭해서** 잡습니다. 타이머 바, 콤보 연출, 펀치/파티클/플로팅 숫자, 등급별 색,
  종료 시 **획득 결과 + 광고 2배 보상** 팝업. (드디어 "손맛"이 생겼습니다.)
- **업그레이드 패널** — 분류별 카드(사냥/요리/식당/방치), 레벨·효과·지수형 비용·구매 버튼.
  살 수 없으면 회색, 사면 즉시 반영.
- **모험 패널** — 세계수 키우기(정수 게이지 + 성장 버튼) + 지역 이동 카드(잠김/이동/현재).
- **직원 패널** — 지역 동물 직원 영입 카드(잠금 사유·비용 표시, 영입 시 패시브 버프).
- **오프라인 정산 팝업** — 재접속 시 누적 수익 + "광고로 2배".
- **연출·사운드** — 손님 서빙 코인 팝업, 해금/영입 토스트, 버튼 눌림 반응,
  코드로 생성한 효과음(탭/코인/구매/레벨업/서빙)과 잔잔한 오르골 BGM(음소거 가능).
- **식당 뷰 개선** — 셰프 아이들 바운스, 손님 머리 위 "원하는 메뉴" 생각풍선, 한글 폰트 적용.

## 🔧 기술 메모

- **새 Input System 전용**(`activeInputHandler: 1`)이라, `GameUIController`가 런타임에 EventSystem +
  `InputSystemUIInputModule`을 (리플렉션으로) 생성해 클릭이 정상 동작하도록 했습니다.
- **프리팹/씬 수작업 없이 전부 코드 생성** — 기존 프로젝트 방식(`ProjectSetup`, `RestaurantView`)과 동일한
  데이터-드리븐/코드-드리븐 철학을 따랐습니다. 빌드에서도 그대로 동작합니다.
- **한글 폰트** — OS 동적 폰트(Apple SD Gothic Neo 등)를 공용으로 만들어 UI와 월드 텍스트 모두 적용.
  (별도 TMP 폰트 에셋 베이킹이 필요 없습니다.)
- **사운드는 전부 런타임 합성** — 외부 오디오 파일 없이 코드로 파형을 생성합니다.
- **TextMeshPro 미사용** — 레거시 uGUI `Text`로 통일(임포트 의존성 제거).
- **기존 로직/밸런스/테스트 무변경** — 매니저 핵심 수식과 `EconomyMathTests`는 그대로입니다.

```
Sprites/Customers/  customer_raccoon · customer_fox · customer_penguin · customer_vipcat

```

적용 위치:

- **손님**: 식당에 앉는 손님이 더 이상 흰 블록이 아니라 종족별 캐릭터로 등장.
- **재료**: 사냥 중 탭하는 타겟과 결과 화면이 단색 원 대신 귀여운 음식 아이콘으로.

  달빛·강물, 동굴은 꿀빛·결정, 설산은 오로라·설산). 지역 이동하면 배경도 바뀝니다.

> 손님·재료 아이콘은 셋업 재실행(`Nyangsta > Setup`) 시 데이터에 연결되고,
> 사냥터 배경은 `Resources`에서 런타임 로드되어 바로 적용됩니다.

## 🕹 아케이드 타이쿤 루프 (My Perfect Hotel / Burger Please 방향)

탭 UI 기반의 "방치형"에서 한 발 더 나아가, **캐릭터를 직접 움직여 자원을 줍고 시설에 넣어
생산·판매하고 돈으로 확장하는 아케이드 타이쿤** 코어를 그레이박스로 완성했습니다.
기존 M1 프로토타입(`Arcade/*`)을 *확장*했고, 백엔드 매니저·경제 로직은 건드리지 않았습니다.

### 핵심 루프
```
캐릭터 직접 이동 → 자원 존에서 자동 수집(스택) → 생산 시설에 투입 →
완성품 픽업 → 손님 테이블에 서빙 → 돈 더미 줍기 → 건설/영입 존에서 확장
```

### 무엇이 생겼나
- **보이는 가상 조이스틱** (`ArcadeJoystick`) — 화면 왼쪽을 터치하면 그 지점에 조이스틱이
  떠오르고 드래그 방향으로 이동. (오른쪽 절반은 향후 버튼용으로 비워둠.) 데스크톱은
  마우스/WASD로도 테스트 가능. 기존의 "보이지 않는 드래그" 입력을 대체.
- **자원 2종 라인** — 생선(강) → 그릴 → 생선구이, **산딸기(밭) → 착즙기 → 산딸기주스**.
  `ArcadeItemType`에 Berry/BerryJuice/Wood/Mushroom·가공품 슬롯 추가(나무·버섯은 다음 확장용).
- **건설 존 확장** — 테이블 2·3, 그리고 **산딸기 라인 전체**가 잠겨 있다가, 돈을 들고 건설 존에
  서 있으면 골드가 빠지며 해금. (`BuildZone` 재사용, 비용 60/140/100G.)
- **직원 자동화** *(후반 핵심)* (`StaffAgent` + `HireZone`) — 영입 존에 돈을 들고 서면 직원이
  고용되어 **내가 하던 동선(수집→투입→서빙)을 그대로 자동 반복**. 라인별로 따로 고용(150/220G).
- **메뉴별 손님 주문** — 손님이 라인 해금 상태에 따라 생선구이/주스를 번갈아 주문(라운드로빈).
  잠긴 라인의 메뉴는 주문되지 않음.

### 새 파일 (`Assets/_Project/Scripts/Arcade/`)
```
ArcadeJoystick.cs   화면에 보이는 플로팅 가상 조이스틱(OnGUI, 캔버스/프리팹 불필요)
StaffAgent.cs       고용 직원 AI — 수집/요리/서빙 동선 자동 수행(StackHolder·존 트리거 재사용)
HireZone.cs         돈을 들고 서서 직원 고용(드레인 결제) → StaffAgent 스폰
```

### 수정(최소·비파괴)
```
Arcade/ArcadeStackItem.cs        ArcadeItemType에 Wood/Mushroom/주스/꼬치 등 확장
Arcade/ArcadePlayerController.cs  보이지 않는 드래그 → ArcadeJoystick 연동
Arcade/ArcadeCustomerSpawner.cs  단일 주문 → 해금 상태 기반 메뉴 라운드로빈
Arcade/ArcadePrototypeBootstrap.cs  2번째 라인·테이블 3개·건설/영입 존·조이스틱 배선
```

### 기술 메모
- **직원은 명시적 Kinematic Rigidbody 필요** — 플레이어는 `CharacterController`라 트리거 이벤트가
  자동 발생하지만, 직원은 트리거 캡슐만이라 (trigger-vs-trigger) Rigidbody가 없으면 존이 인식하지
  못함. `HireZone.SpawnStaff`에서 `isKinematic` 바디를 붙여 해결. (M1 세팅 가이드의 "CharacterController는
  Rigidbody 불필요" 메모의 역(逆) 케이스.)
- **존이 일을 한다** — `StaffAgent`는 *어디에 설지*만 결정하고, 실제 수집/요리/서빙은 기존
  `GatherZone`/`CookStation`/`TableZone`의 `OnTriggerStay`가 플레이어와 동일하게 처리. 자동화 코드를
  중복하지 않음.
- **전부 코드 생성** — 프리팹/씬 수작업 없이 `ArcadePrototypeBootstrap`이 런타임에 월드를 구성(기존 철학 유지).

## 🎨 아케이드 2.5D 비주얼 (큐브 → 스프라이트)

큐브·캡슐 그레이박스였던 아케이드 맵을 **귀여운 스토리북 스타일 2.5D 스프라이트 월드**로 교체했습니다.
**시뮬레이션(이동·트리거·직원 AI)은 3D 그대로 두고 보이는 것만 스프라이트로** 바꾸는 방식이라
(= My Perfect Hotel식 "종이 인형" 룩), 기존 게임플레이 코드는 동작 변경 없이 그대로 돌아갑니다.

### 새 아트 (20종, SVG→PNG `rsvg-convert`)
`Assets/_Project/Resources/Arcade/` (런타임 `Resources.Load`):
```
바닥 타일   tile_grass · tile_wood · tile_path · tile_water · tile_berryfield
시설        grill · juicer · table · pad_build · pad_hire
캐릭터      player(셰프냥) · staff(직원냥, 파랑)
아이템      item_fish · item_grilledfish · item_berry · item_juice · money
소품        tree · bush · fence
손님        cust_*  (기존 customer_* 일러스트 6종을 Resources로 복사해 재사용)
```
생성기: `tools/arcade_art/gen_arcade_sprites.py` (기존 아트와 동일 SVG 파이프라인, 팔레트 통일)

### 새 파일 (`Assets/_Project/Scripts/Arcade/`)
```
ArcadeSprites.cs    런타임 스프라이트 로더(Texture2D→Sprite.Create, 캐시).
                    피벗 2종: 바닥접지(캐릭터/시설/소품) vs 중앙(아이템/타일).
                    타일은 코스 PPU(75)로 만들어 바닥 반복이 너무 잘지 않게.
SpriteBillboard.cs  앵글드 직교 카메라에서 스프라이트를 세워 카메라 피치에 맞춰 기울이고,
                    월드 Z/Y로 sortingOrder를 매겨 앞뒤(겹침)를 정렬.
```

### 수정
```
ArcadePrototypeBootstrap.cs  큐브/캡슐 메시는 숨기고(콜라이더 유지) 스프라이트 부착.
                             바닥=타일드 스프라이트, 카메라 50°/size 6.2, 소품 배치.
ArcadeCustomer.cs            손님 몸체 스프라이트 + ApplySprite로 종족별 일러스트 교체.
ArcadeCustomerSpawner.cs     손님마다 cust_* 일러스트를 라운드로빈으로 배정(줄이 다양).
HireZone.cs                  직원 캡슐 메시 숨김 + staff 스프라이트(머티리얼 인자 제거).
ArcadeCameraFollow.cs        피치 50° 동기화, 부드러운 추적.
Editor/SpriteImportSettings.cs  Resources/Arcade PNG를 Texture로 클린 임포트(밉맵 끄고 Repeat).
```

### 기술 메모
- **3D 시뮬 유지 + 스프라이트 빌보드** = 2.5D. 이동/충돌/직원 AI는 전혀 안 건드리고 렌더만 교체해
  안전. 콜라이더는 살리고 `MeshRenderer`만 끔(특히 바닥은 콜라이더 유지해야 `CharacterController`가 섬).
- **피벗 2종** — 캐릭터·시설·소품은 바닥접지 피벗으로 "땅에 서고", 아이템·타일은 중앙 피벗.
  바닥 타일은 `SpriteDrawMode.Tiled` + `SpriteMeshType.FullRect`로 반복.
- **정렬** — `SpriteBillboard`가 매 프레임 Z/Y 기반 `sortingOrder`를 계산, 카메라 `transparencySortMode`도
  뷰축으로 맞춰 같은 order 충돌 시에도 앞뒤가 자연스럽게.
- **검증** — Unity 6000.4.10f1 어셈블리로 런타임·에디터 어셈블리 **컴파일 에러/경고 0개**. (단,
  비주얼 자체는 에디터에서 Play로 확인 필요 — 헤드리스 렌더는 안 함.)

## 🖌 아트 리디자인 — 컨셉 아트 반영 (v2)

`Art/Concepts/`의 13장 컨셉(따뜻한 스토리북 일러스트)을 기준으로 아케이드 스프라이트를 **다시 디자인**.
초안의 단순 플랫 벡터 → **칼라고(삼색) 고양이 + 통나무 식당 분위기**로 톤을 맞췄어.

### 무엇이 바뀌었나
- **플레이어 = 칼라고 셰프냥** — 흰 바탕 + 주황/검정 비대칭 패치(귀·볼), 큰 호박색 눈, 셰프 토크 +
  빨강 트림 코트 + 목수건. (컨셉 `chef_nyastar_calico` 반영)
- **직원 = 칼라고 탐험가냥** — 같은 삼색 고양이 + 초록 유틸리티 조끼(주머니·나침반 버클).
  (컨셉 `bipedal_nyastar_calico` 반영) → 플레이어와 한눈에 구분.
- **따뜻한 팔레트** — 깊은 통나무색 바닥/테이블, 호박색 랜턴, 따뜻한 외곽선(warm outline)으로
  손그림 스토리북 느낌. 그릴·착즙기·아이템·타일·나무·덤불·울타리 전부 톤 맞춤.
- **랜턴 소품 추가** — 통나무 식당의 아늑한 조명(컨셉 인테리어 분위기).
- **손님은 기존 일러스트 6종 유지** — `cust_*`(토끼·너구리·여우·곰·펭귄·VIP고양이)은 이미 컨셉급
  일러스트라 그대로 사용(라운드로빈 등장).

### 파일
```
tools/arcade_art/gen_arcade_sprites_v2.py   리디자인 생성기(칼라고 고양이 + 따뜻한 팔레트)
Assets/_Project/Resources/Arcade/*.png      재생성/교체된 스프라이트 (player, staff, grill,
                                            juicer, table, item_*, tile_*, tree/bush/fence/lantern, pad_*)
```

### 기술 메모 (LFS 주의)
- **이 프로젝트의 모든 PNG는 Git LFS** — 브랜치 전환 후 작업트리에 130바이트 **포인터 텍스트**만 남는
  경우가 잦음(`file`이 "ASCII text", `version https://git-lfs...`로 시작). 그러면 Unity가 텍스처로
  못 읽음. 로컬 캐시(`.git/lfs/objects`)에 객체가 있으면 `git lfs smudge < a.png > a.png`로 실제
  바이트를 복원. (이번에 `cust_*` 6종이 포인터라 이 방식으로 복원함.)
- 리디자인 후 런타임 어셈블리 **컴파일 에러 0개**. 비주얼은 에디터 Play로 확인 필요.
