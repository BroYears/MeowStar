## 1. 게임 개요 (Overview)

### 1.1 한 줄 컨셉

> **“숲에서 직접 사냥해 재료를 구하고, 그 재료로 요리해 동물 손님에게 파는 고양이 셰프의 방치형 키친.”**
> 

### 1.2 엘리베이터 피치

플레이어는 작은 식당을 운영하는 고양이 셰프 **냥스타**가 된다. 직접 숲으로 나가 간단한 터치 사냥 미니게임으로 재료(생선, 고기, 채소 등)를 모으고, 식당으로 돌아와 요리해 찾아오는 동물 손님들에게 판매한다. 번 골드로 주방·식당·사냥 도구를 업그레이드하면, 자리를 비운 사이에도 직원(또는 자동화)이 돈을 벌어주는 방치형 수익이 쌓인다. **“잠깐의 능동적 사냥 + 길게 누적되는 방치 수익”** 의 결합이 핵심 재미다.

### 1.3 핵심 재미 (Core Pillars)

1. **즉각적인 손맛** — 짧고 경쾌한 사냥 미니게임. 한 손으로 5~15초 안에 끝나는 부담 없는 루프.
2. **성장의 쾌감** — 골드 → 업그레이드 → 더 큰 수익. 눈에 띄게 좋아지는 식당과 메뉴.
3. **귀여움(냥·동물)** — 고양이 셰프와 다양한 동물 손님이 주는 수집·관찰 재미.
4. **방치 보상** — 접속하지 않아도 쌓이는 수익. 다시 켰을 때의 “오프라인 수익 정산” 도파민.

### 1.4 타깃 유저

- **1차 타깃**: 출퇴근·자투리 시간에 즐기는 캐주얼·방치형 게임 유저 (10대 후반~30대).
- **2차 타깃**: 동물·요리·꾸미기 테마를 좋아하는 라이트 유저.
- **참고 게임**: 방치형 요리·상점 경영 게임군(예: 어비스리움류의 누적 성장, 카페·식당 타이쿤류의 경영 루프, 캐주얼 사냥/낚시 미니게임의 손맛).

### 1.5 디자인 목표 & 비목표

**목표(Do)**
- 첫 60초 안에 “사냥 → 요리 → 판매 → 골드 획득”의 핵심 루프를 한 바퀴 경험시킨다.
- 한 손 세로 플레이로 모든 핵심 조작이 가능해야 한다.
- 2인 개발 범위 안에서 출시 가능한 콘텐츠 양으로 설계한다.

**비목표(Don’t)**
- 복잡한 실시간 멀티플레이/PvP 없음 (초기 범위 제외).
- 정밀한 물리 시뮬레이션·3D 풀 그래픽 없음 (2D/2.5D 카툰 스타일).
- 무거운 스토리 분기 없음 (가벼운 세계관·이벤트 중심).

## 2. 세계관 & 캐릭터 (Story & World)

### 2.1 배경 설정

숲속 작은 마을에 자리 잡은 식당 **“냥스타 키친”**. 주인장 고양이 셰프 냥스타는 “세상에서 가장 신선한 재료는 직접 구한다”는 신념으로, 매일 숲과 강으로 나가 재료를 사냥·채집한다. 입소문을 타고 토끼, 너구리, 곰, 여우 등 다양한 동물 손님이 찾아오면서 식당은 점점 커진다.

### 2.2 핵심 캐릭터

| 캐릭터 | 역할 | 특징 |
| --- | --- | --- |
| **냥스타** | 플레이어(고양이 셰프) | 사냥·요리·운영의 주체. 외형/복장 커스터마이즈 여지. |
| **동물 손님** | NPC | 종류별 선호 메뉴·지불 골드·인내심이 다름. (토끼/너구리/곰/여우/펭귄 등) |
| **직원(고용)** | 자동화 NPC | 후반부 해금. 방치 시 자동 사냥·서빙으로 수익 발생. |

> 핵심 캐릭터(냥스타, 대표 동물 4~5종)는 **직접 제작**, 나머지 군중·배경은 **외부 에셋 활용**. (역할분담의 아트 전략과 일치)
> 

### 2.3 톤 & 무드

밝고 따뜻한 파스텔 카툰. 코미컬하고 귀여운 분위기. 폭력적 사냥 묘사는 배제하고, “통통 튀는 재료를 잡는” 추상적·만화적 연출로 표현한다.

## 3. 코어 게임플레이 루프 (Core Loop)

### 3.1 단기 루프 (수십 초 ~ 수 분)

```
[사냥터 입장] → [사냥 미니게임으로 재료 획득] → [식당 복귀]
      → [재료로 요리] → [동물 손님 주문 응대·판매] → [골드 획득] → 반복
```

### 3.2 중기 루프 (한 세션, 수 분 ~ 수십 분)

```
골드 누적 → 업그레이드(주방/메뉴/사냥도구/식당 확장) 구매
      → 더 비싼 메뉴·더 좋은 손님 해금 → 수익 증가 → 다음 목표 달성
```

### 3.3 장기 루프 (며칠 ~ 수주)

```
스테이지(지역) 해금 → 신규 재료·메뉴·손님 등장 → 직원 고용으로 방치 자동화
      → 환생/프레스티지(선택적) → 영구 성장 보너스 → 신규 콘텐츠 도전
```

### 3.4 방치(오프라인) 루프

앱을 종료/백그라운드 상태에서도 시간당 일정 골드가 누적된다. 재접속 시 **오프라인 수익 정산 팝업**으로 보상을 지급하고, 보상형 광고로 “정산액 2배” 옵션을 제공한다.

## 4. 핵심 시스템 상세 (Core Systems)

### 4.1 사냥 미니게임 (Hunting Mini-game)

게임의 능동적 재미를 담당하는 짧은 터치 미니게임.

- **목표**: 제한 시간(예: 15초) 안에 화면에 등장하는 재료를 최대한 많이 터치해 획득.
- **조작**: 단일 탭(tap). 화면 곳곳에 나타났다 사라지는 재료를 정확히 탭.
- **판정**: 등장 → 유효 탭 시 획득 + 점수. 빗나가거나 시간 초과 시 사라짐.
- **콤보**: 연속 성공 시 콤보 배수 증가 → 획득량/희귀도 보너스.
- **쿨타임/스태미나**: 사냥 1회당 스태미나 소모. 스태미나는 시간 회복 또는 광고/아이템으로 즉시 회복.
- **변주(스테이지별)**: 강(낚시형: 타이밍 탭), 숲(이동 표적), 동굴(희귀 재료, 난이도↑) 등 같은 메커니즘의 스킨 변주.
- **결과**: 획득 재료 종류·수량 + 보너스 골드. 희귀 재료일수록 고급 메뉴 재료가 됨.

**튜닝 파라미터**: 제한시간, 재료 등장 빈도/속도, 재료별 출현 확률, 콤보 배수 테이블, 스태미나 소모/회복량.

### 4.2 요리 / 조리 시스템 (Cooking)

- 보유 재료를 **레시피**에 따라 조합해 메뉴를 생산한다.
- 초기에는 **탭 1회 = 1요리 완성**의 단순 방식. 업그레이드로 조리 속도·동시 조리 수 증가.
- 메뉴마다 **필요 재료·조리 시간·판매가**가 정해져 있다.
- 후반부: 조리대 추가 설치, 자동 조리(직원) 해금.

### 4.3 손님(동물) 시스템 & AI

- **스케줄러**가 일정 간격으로 손님을 입장시킨다. (입장 → 자리 착석/대기 → 주문 → 음식 제공 → 결제·퇴장)
- 손님마다 **선호 메뉴, 지불 골드, 인내심(대기 한계)** 속성이 다르다.
- 인내심이 0이 되면 화내며 퇴장(수익 손실 + 평판 소폭 하락).
- 손님 종류는 스테이지 진행/평판에 따라 해금. 고급 손님일수록 높은 골드 지불.
- **AI 구현**: 유한 상태 기계(FSM) — `입장 → 대기 → 주문 → 식사 → 결제 → 퇴장`. (기술 섹션 11.4 참조)

### 4.4 경제 시스템 (Economy)

게임의 척추. 모든 진행이 골드를 매개로 연결된다.

- **재화 종류**
    - **골드(Gold)**: 기본 소프트 재화. 판매·방치 수익으로 획득, 업그레이드에 사용.
    - **보석(Gem)**: 하드 재화. 광고·IAP·일부 보상으로 획득. 시간 단축·프리미엄 해금에 사용.
    - **재료(Ingredients)**: 사냥으로 획득하는 중간 자원. 요리에 소비.
- **수익 흐름**: 판매 골드 = Σ(메뉴 판매가 × 판매 수량) + 콤보/이벤트 보너스 + 방치 수익.
- **지출 흐름**: 업그레이드 비용, 시간 단축, 식당 확장.

**업그레이드 비용 곡선 (지수형)**

```
다음_레벨_비용 = 기본비용 × (성장계수 ^ 현재레벨)
예) 기본비용 100, 성장계수 1.15
Lv0→1: 100, Lv1→2: 115, Lv2→3: 132, Lv3→4: 152 ...
```

- 수익 증가율(성장계수 ~1.07)은 비용 증가율(~1.15)보다 낮게 설정해, 새 업그레이드 라인을 계속 해금하도록 유도한다(방치형 표준 패턴).

### 4.5 방치형 수익 (Idle Income)

- **시간당 기본 수익(GPS, Gold Per Second)** = Σ(자동화된 메뉴 판매율 × 판매가) × 직원 효율.
- 오프라인 누적 상한(예: 최대 8시간)을 둔다. 상한·효율은 업그레이드/광고로 확장.
- 재접속 시 정산 팝업 → 보상형 광고로 2배 옵션.
- 초반에는 방치 수익 비중이 낮고(능동 플레이 유도), 직원 고용 후 비중이 커진다.

### 4.6 진행 / 스테이지 (Progression)

- **지역(스테이지)** 단위로 콘텐츠를 묶는다: 숲 → 강가 → 설산 → 동굴 …
- 각 지역은 신규 재료·메뉴·손님·배경을 제공.
- 해금 조건: 누적 골드, 식당 레벨, 또는 특정 메뉴 판매량 달성.
- (선택) **프레스티지/환생**: 진행을 리셋하고 영구 배수 보너스를 얻는 후반 콘텐츠.

## 6. UI / UX 설계

### 6.1 화면 구성 (Scenes / Screens)

- **메인 식당 화면(홈)**: 식당 전경, 손님·조리 연출, 상단 재화 HUD, 하단 메뉴 탭(상점/업그레이드/사냥/설정).
- **사냥 화면**: 지역 배경 + 미니게임 인터랙션 영역 + 타이머/콤보/획득 표시.
- **업그레이드 패널**: 분류별 탭, 항목 리스트, 비용·효과·구매 버튼.
- **상점**: 보석 IAP, 광고 보상, 시간 단축 아이템.
- **결과/정산 팝업**: 사냥 결과, 오프라인 수익 정산(+광고 2배).
- **튜토리얼 오버레이**: 핵심 루프 1회를 강제 가이드.

### 6.2 화면 흐름 (Screen Flow)

```
[스플래시/로고]
   → [타이틀] → (최초 1회) [튜토리얼]
   → [메인 식당(홈)] ⇄ [사냥 화면] ⇄ [결과 팝업]
        ⇅
   [업그레이드/상점/설정 패널]
```

### 6.3 UX 원칙

- **세로 한 손 플레이**. 주요 버튼은 화면 하단 thumb-zone에 배치.
- **3탭 이내** 로 모든 핵심 기능 도달.
- **즉각 피드백**: 골드 획득·레벨업·해금 시 사운드 + 파티클 + 숫자 팝업.
- **점진적 노출**: 초반엔 사냥·요리만, 진행하며 업그레이드·방치·상점을 순차 공개.

### 6.4 온보딩 / 튜토리얼

첫 실행 시 강제 가이드로 한 사이클을 체험시킨다: 사냥 1회 → 요리 1회 → 손님 1명 응대 → 골드 획득 → 첫 업그레이드 구매. 이후 자유 플레이로 전환.

### 7.1 비주얼 스타일

- UI는 둥근 모서리·말랑한 버튼·큼직한 아이콘으로 캐주얼 감성 유지.

## 11. 기술 설계 (Technical Design — Unity)

> 2인 분담: **개발자 A = 게임플레이·경제·백엔드 시스템**, **개발자 B = UI/UX·씬흐름·콘텐츠 데이터**. (섹션 13 참조)
> 

### 11.1 아키텍처 개요

- **데이터-드리븐 설계**: 모든 콘텐츠(재료·메뉴·손님·업그레이드)는 ScriptableObject 자산으로 정의 → 코드 수정 없이 밸런싱.
- **매니저 중심 구조**: 핵심 시스템마다 단일 책임 매니저(싱글톤 또는 서비스 로케이터)로 분리.
- **이벤트 기반 통신**: 시스템 간 결합도를 낮추기 위해 C# `event`/`Action` 또는 가벼운 이벤트 버스 사용 (예: 골드 변동 → HUD 자동 갱신).

```
        ┌──────────────┐
        │ GameManager  │  (전체 상태/씬 조율)
        └──────┬───────┘
   ┌───────────┼─────────────┬───────────────┬──────────────┐
┌──┴───┐  ┌────┴────┐  ┌─────┴─────┐  ┌──────┴─────┐  ┌─────┴─────┐
│Economy│  │Hunting  │  │Customer   │  │Save        │  │Ads / UI   │
│Manager│  │Manager  │  │Manager(FSM)│  │Manager     │  │Manager    │
└───────┘  └─────────┘  └───────────┘  └────────────┘  └───────────┘
       (A)        (A)          (A)            (A)         (A광고/B UI)
```

### 11.2 씬(Scene) 구조

- **단일 메인 씬 + Additive 로딩** 방식 권장(전환 비용 최소화·방치형 특성).
    - `Bootstrap` 씬: 초기화(세이브 로드, 매니저 생성, SDK init) → 메인으로 전환.
    - `Main` 씬: 식당 홈. 사냥/상점/업그레이드는 **씬 내 패널(UI)** 또는 Additive 서브씬으로 처리.
- 또는 단순화를 위해 **단일 씬 + 패널 토글** 구조도 가능(2인 개발 시 권장). 사냥은 같은 씬의 오버레이 상태로 구현.
- 화면 흐름·전환 애니메이션·로딩은 개발자 B 담당.

### 11.3 데이터 아키텍처 (ScriptableObject)

콘텐츠는 코드가 아닌 **에셋**으로 관리한다. 개발자 B가 데이터 자산을 채우고, 개발자 A의 시스템이 이를 소비한다.

```csharp
// 재료 정의
[CreateAssetMenu(menuName = "Nyangsta/Ingredient")]
public class IngredientData : ScriptableObject {
    public string id;
    public string displayName;
    public Sprite icon;
    public Rarity rarity;          // Common, Rare, Epic, Legendary
    public RegionType region;      // Forest, River, Cave, Snow
    [Range(0,1)] public float spawnRate;
}

// 메뉴(레시피) 정의
[CreateAssetMenu(menuName = "Nyangsta/Menu")]
public class MenuData : ScriptableObject {
    public string id;
    public string displayName;
    public Sprite icon;
    public IngredientRequirement[] requirements; // 재료+수량
    public float cookTime;
    public int sellPrice;
    public UnlockCondition unlock;
}

// 손님 정의
[CreateAssetMenu(menuName = "Nyangsta/Customer")]
public class CustomerData : ScriptableObject {
    public string id;
    public string displayName;
    public MenuData preferredMenu;
    public float payMultiplier;
    public float patienceSeconds;
    public int unlockStage;
}

// 업그레이드 정의 (지수형 비용 곡선)
[CreateAssetMenu(menuName = "Nyangsta/Upgrade")]
public class UpgradeData : ScriptableObject {
    public string id;
    public UpgradeCategory category;
    public double baseCost;
    public float costGrowth;       // 예: 1.15
    public float effectPerLevel;   // 레벨당 효과량
    public int maxLevel;           // 0 = 무한
}
```

전체 콘텐츠는 `ScriptableObject` 자산 목록을 들고 있는 **Database SO**(예: `GameDatabase`)에서 id로 조회한다.

### 11.4 핵심 매니저 (Manager Responsibilities)

| 매니저 | 담당 | 핵심 기능 |
| --- | --- | --- |
| `GameManager` | A | 전역 상태, 게임 시작/일시정지, 씬·흐름 조율 |
| `EconomyManager` | A | 골드/보석/재료 잔액, 수익·지출 처리, 업그레이드 비용 계산, GPS(방치 수익) |
| `HuntingManager` | A | 사냥 미니게임 진행, 입력 판정, 콤보, 재료 드랍 |
| `CustomerManager` | A | 손님 스폰 스케줄러 + FSM(입장→대기→주문→식사→결제→퇴장) |
| `SaveManager` | A | 저장/불러오기, 오프라인 시간 계산, 자동 저장 |
| `AdManager` | A | AdMob 보상형/전면 광고 로드·표시·콜백 |
| `UIManager` | B | 패널 스택, HUD 갱신, 팝업, 화면 전환 |
| `SceneFlow` | B | 부트스트랩→타이틀→튜토리얼→메인 흐름 |
| `SoundManager` | B | BGM/SFX 재생, 볼륨 설정 |
| `LocalizationManager` | B | 텍스트 키-값 테이블, 언어 전환 |

**손님 FSM 예시**

```csharp
public enum CustomerState { Entering, Waiting, Ordering, Eating, Paying, Leaving }
// Waiting 중 patience 타이머 감소 → 0이면 Leaving(불만), 음식 제공 시 Eating으로 전이
```

### 11.5 저장 / 불러오기 (Save System)

- **방식**: JSON 직렬화(`JsonUtility` 또는 Newtonsoft) → 파일(`Application.persistentDataPath`). 단순 설정값은 `PlayerPrefs` 보조 사용.
- **저장 데이터**: 재화 잔액, 업그레이드 레벨, 해금 상태, 스테이지 진행, 마지막 종료 시각(오프라인 정산용), 설정(사운드/언어), 광고 제거 여부.
- **오프라인 정산**: 재접속 시 `현재시각 − 마지막종료시각`(상한 적용) × GPS = 누적 골드.
- **자동 저장**: 주요 상태 변경 시 + 앱 일시정지(`OnApplicationPause`)/종료 시점 저장.
- **무결성**: 저장 데이터에 버전 필드를 두어 마이그레이션 대비. (선택) 간단한 체크섬으로 변조 방지.

```csharp
[Serializable]
public class SaveData {
    public int version = 1;
    public double gold;
    public int gems;
    public Dictionary<string,int> upgradeLevels;
    public List<string> unlockedStages;
    public long lastQuitUnixTime;
    public SettingsData settings;
    public bool adsRemoved;
}
```

### 11.6 광고 SDK 연동 (Google AdMob)

- **패키지**: Google Mobile Ads Unity 플러그인.
- **초기화**: `Bootstrap`에서 `MobileAds.Initialize()`. 개발 중에는 **테스트 광고 단위 ID** 사용.
- **보상형**: 사전 로드 → 시청 완료 콜백에서 보상 지급(오프라인 2배·스태미나 회복 등). 실패 시 graceful fallback.
- **전면**: 자연스러운 전환 지점에서만, 빈도 제한.
- **동의/정책**: iOS ATT(App Tracking Transparency), GDPR 동의 처리(UMP SDK). 아동 대상 정책 검토.
- 광고 호출은 `AdManager`로 일원화해 게임 로직과 분리(개발자 A).

### 11.8 협업 & 빌드 파이프라인

- **버전 관리**: Git + **Git LFS**(대용량 에셋). `.gitignore`는 Unity 표준 템플릿 사용. 씬·프리팹 충돌 최소화를 위해 작업 영역 분리(A=로직 스크립트, B=UI/씬).
- **씬 충돌 방지**: 단일 씬 다인 작업 시 프리팹 단위로 분리 편집, 머지 전 사전 합의.
- **빌드**: 개발자 A가 Android(.aab)/iOS 빌드 설정·키스토어·서명·스토어 업로드 관리. 가능하면 Unity Cloud Build 또는 로컬 빌드 스크립트로 반복 빌드 자동화.
- **테스트**: 핵심 경제 계산(비용 곡선, 오프라인 정산)은 EditMode 단위 테스트로 검증.

## 13. 팀 역할 분담 (2인)

기본 원칙: **아트는 외부 에셋 + 핵심만 직접**, **기획은 함께 결정·문서화는 분담**, **개발은 시스템 성격별 분리**.

### 🅐 개발자 A — 게임플레이 & 백엔드 (게임의 두뇌)

- **개발**: 사냥 미니게임 로직(입력·판정·쿨타임), 경제 시스템(골드·업그레이드 트리·방치 수익), 손님 AI(FSM 스케줄러), 저장/불러오기, AdMob 연동, 빌드 파이프라인(Android/iOS).
- **기획**: 경제 밸런스 수치(획득량·비용 곡선), 사냥 규칙 정의, 난이도 커브 스프레드시트.
- **아트**: UI 버튼·아이콘 연동 코드, 파티클 이펙트 세팅.

### 🅑 개발자 B — UI/UX & 콘텐츠 (게임의 얼굴)

- **개발**: 전체 UI(메인·상점·업그레이드·HUD), 씬 전환·화면 흐름(튜토리얼→메인→결과), 애니메이션 연동(Animator), 사운드 매니저, 로컬라이제이션 텍스트 시스템.
- **기획**: 전체 콘텐츠 데이터 관리(메뉴·손님·재료 → ScriptableObject), 튜토리얼 흐름 설계·구현, 스테이지·이벤트 시나리오.

### 공동

- 코어 루프·세계관·수익화 방향은 **함께 결정**.
- 에셋 라이선스 추적 시트 공동 관리.

## 15. 부록 — 용어 & 참고

- **GPS (Gold Per Second)**: 방치 시 초당 자동 골드 수익.
- **FSM (Finite State Machine)**: 손님 행동 상태 관리에 사용하는 유한 상태 기계.
- **SO (ScriptableObject)**: Unity의 데이터 자산. 콘텐츠 정의·밸런싱에 사용.
- **소프트/하드 재화**: 골드(플레이로 획득) / 보석(광고·결제로 주로 획득).
- **프레스티지**: 진행 리셋 대가로 영구 배수 보너스를 얻는 후반 성장 시스템.
