## 1. 게임 개요 (Overview)

### 1.1 한 줄 컨셉
> **"고양이 셰프를 조이스틱으로 직접 움직여 — 숲에서 재료를 주워 머리에 쌓고, 돌아와 요리하고, 손님에게 나르고, 바닥의 돈을 쓸어 담는 — 한 손 레스토랑 타이쿤."**

### 1.2 엘리베이터 피치
플레이어는 고양이 셰프 **냥스타**를 조이스틱 하나로 움직인다. 버튼은 없다. **그릴 앞에 서면 요리가 되고, 손님 테이블에 가면 서빙이 되고, 계산대에 서면 결제가 진행된다.** 식당 뒤 숲으로 걸어가면 통통 튀는 재료(생선·산딸기·버섯)가 캐릭터에게 빨려 들어와 머리 위로 쌓인다. 손님이 놓고 간 지폐 더미를 지나가며 쓸어 담고, 그 돈을 새 구역에 들고 서 있으면 새 시설이 "펑" 하고 지어진다. 직원 고양이를 고용하면 내가 하던 일이 하나씩 자동화되고, 접속하지 않아도 수익이 쌓인다. **"내 발로 뛰는 손맛 → 점점 자동화되는 성장 → 방치 수익"** 의 검증된 장르 공식에 고양이·동물·요리의 귀여움을 얹는다.

### 1.3 핵심 재미 (Core Pillars)
1. **이동 = 모든 조작** — 조이스틱 하나, 버튼 0개. 캐릭터가 존(zone)에 서 있으면 행동이 자동 수행된다. 5초 안에 배우는 직관성.
2. **스태킹의 손맛** — 재료·음식을 머리 위로 높이 쌓아 나르는 시각적 만족. 업그레이드할수록 더 높이 쌓는다.
3. **돈을 쓸어 담는 도파민** — 손님이 테이블·계산대에 놓고 간 지폐 더미를 캐릭터가 지나가며 흡수. 코인 사운드 + 숫자 팝업.
4. **눈에 보이는 확장** — 돈을 들고 건설 존에 서 있으면 새 시설·새 구역이 지어진다. 식당이 커지는 게 한눈에 보인다.
5. **귀여움과 자동화** — 고양이 셰프·동물 손님·직원 고양이. 내가 하던 일을 직원이 대신하는 걸 구경하는 재미 + 방치 보상.

### 1.4 타깃 유저
- **1차 타깃**: 출퇴근·자투리 시간 캐주얼/하이브리드 캐주얼 유저 (10대 후반~30대). 장르 평균 D1 리텐션 35~50%, 첫날 플레이 25분.
- **2차 타깃**: 동물·요리 테마를 좋아하는 라이트 유저 (Cat Snack Bar 유저층과 동일).
- **핵심 레퍼런스**:
  - **My Perfect Hotel** — 존 기반 행동(서 있으면 게이지 진행), 마이크로태스크 동선 설계.
  - **Burger Please!** — 스태킹, 스테이션 단위 업그레이드, 프랜차이즈 확장. *2인 팀(개발+PM)이 만든 게임.*
  - **Cat Snack Bar** — 고양이+식당 테마, 스트레스 없는 진행 톤.

### 1.5 디자인 목표 & 비목표
**목표(Do)**
- 첫 60초 안에 "재료 줍기 → 요리 → 서빙 → 돈 줍기 → 첫 업그레이드"를 튜토리얼 텍스트 없이(화살표 가이드만으로) 경험시킨다.
- 모든 조작은 조이스틱 하나. 세로 한 손 플레이.
- 2인 개발 범위: 1차 출시는 식당 1개(숲 식당) + 확장 슬롯 전체, 2호점(강가)은 업데이트로.

**비목표(Don't)**
- 별도 미니게임 씬 없음 — 사냥도 같은 맵 안의 "숲 구역 동선"으로 통합.
- 실시간 멀티/PvP, 무거운 스토리 없음.
- 고품질 3D 아님 — 로우폴리 + 단색 팔레트(에셋 스토어 활용).

## 2. 세계관 & 캐릭터 (Story & World)

### 2.1 배경 설정
숲속 공터에 차린 작은 노점에서 시작한다. 주인장 고양이 셰프 냥스타는 "세상에서 가장 신선한 재료는 직접 구한다"는 신념으로 식당 뒤 숲·강에서 재료를 직접 채집한다. 입소문을 타고 동물 손님이 몰려들면, 노점 → 오두막 식당 → 2층 레스토랑으로 **같은 맵 위에서** 점점 확장된다.

### 2.2 핵심 캐릭터
| 캐릭터 | 역할 | 특징 |
|--------|------|------|
| **냥스타** | 플레이어 조작 캐릭터 | 조이스틱으로 이동. 스택 용량·이동 속도·채집 속도가 성장 스탯. 복장 커스터마이즈(후속). |
| **동물 손님** | NPC (NavMesh 이동) | 입장 → 줄서기 → 착석 → 주문 → 식사 → 결제(돈 떨굼) → 퇴장. 종류별 주문량·지불액·인내심 차등. |
| **직원 고양이** | 자동화 NPC | 고용 시 역할 1개 수행(채집/조리/서빙/계산). 플레이어와 동일한 동선을 AI로 수행 — "내 일을 대신하는 게 보임". |

### 2.3 톤 & 무드
밝고 따뜻한 로우폴리 카툰. 폭력적 사냥 묘사 없음 — 재료는 "통통 튀어다니는 식재료를 줍는" 연출(나무를 톡 치면 산딸기가 떨어지고, 강에서 물고기가 폴짝 뛰어오름).

## 3. 코어 게임플레이 루프 (Core Loop)

### 3.1 분 단위 루프 (Moment-to-moment)
```
[숲/강 구역으로 이동] → 재료가 머리 위로 자동 스태킹
  → [조리 스테이션 존에 서기] → 재료 소모, 요리 게이지 진행, 완성 음식 스태킹
  → [손님 테이블/카운터로 이동] → 자동 서빙
  → [손님이 떨군 지폐 더미 위를 지나감] → 골드 흡수
  → [건설/업그레이드 존에 돈 들고 서기] → 시설 확장
```
**핵심**: 위 모든 단계가 "이동 + 서 있기"만으로 수행된다. 재미의 원천은 **동선 최적화** — 어떤 순서로 돌면 가장 효율적인가를 플레이어가 스스로 발견한다.

### 3.2 세션 루프 (수 분 ~ 수십 분)
```
골드 누적 → 스테이션 업그레이드(속도/용량) 또는 새 구역 건설
  → 손님 증가·고급 메뉴 해금 → 혼자서 못 돌리는 시점 도달(의도된 병목)
  → 직원 고용 → 내 역할이 자동화 → 더 상위 동선에 집중
```

### 3.3 장기 루프 (며칠 ~ 수주)
```
식당 풀 확장 → 식당 레벨업(외형 변화: 노점→오두막→레스토랑)
  → 2호점(강가) 해금 [업데이트] → 신규 재료·메뉴·손님
  → (선택) 프레스티지: 1호점 매각 → 영구 배수 보너스
```

### 3.4 방치(오프라인) 루프
직원이 배치된 작업은 오프라인에서도 수익 발생. 재접속 시 **오프라인 수익 정산 팝업** + 보상형 광고 "2배 받기". 초반엔 직원이 없어 방치 수익이 거의 없고(능동 플레이 유도), 직원을 채울수록 방치형으로 전환된다.

## 4. 핵심 시스템 상세 (Core Systems)

### 4.1 캐릭터 조작 & 존 인터랙션 (장르 핵심)
- **조작**: 화면 아무 곳이나 터치+드래그 = 플로팅 조이스틱. 버튼 없음.
- **존(Zone) 시스템**: 맵의 모든 인터랙션은 바닥의 원형/사각 존으로 표현.
  - 존에 **들어가면** 즉시 행동 시작 (집기/내려놓기는 즉시, 작업류는 게이지).
  - 존에 **서 있는 동안** 게이지 진행 (조리, 건설, 계산).
  - 존을 **벗어나면** 게이지 일시정지 (리셋 아님 — 스트레스 최소화).
- **존 종류**: 채집 존(숲·강), 조리 존(그릴·오븐), 픽업 존(완성 음식 집기), 서빙 존(테이블), 계산 존(카운터), 건설 존(돈 투입), 쓰레기 존(테이블 치우기, 중반 해금).
- **피드백**: 존 진입 시 존이 밝아지고 캐릭터 머리 위 게이지 + 진동(햅틱) 1회. 완료 시 파티클 + 효과음.

### 4.2 스태킹 & 운반 (Stacking)
- 재료·음식·쓰레기는 캐릭터 **머리 위에 물리적으로 쌓인다** (스프링 느낌의 출렁임 연출).
- **스택 용량**: 초기 3개 → 업그레이드로 확장 (최대 20+). 용량 초과 시 더 못 집음(존에서 자동 정지).
- **종류 혼합 불가**: 한 번에 한 종류만 운반 (동선 선택의 의미 부여). 단, 후반 "트레이 업그레이드"로 2종 혼합 해금.
- **내려놓기**: 해당 존에 들어가면 1개씩 빠르게 자동 이동(슉슉 날아가는 연출).

### 4.3 채집 (구 사냥 시스템 → 동선으로 통합)
별도 미니게임 씬을 없애고, **식당 맵 가장자리의 채집 구역**으로 통합한다.
- **숲 구역**: 산딸기 덤불·버섯 — 존에 서 있으면 일정 간격으로 톡톡 떨어져 스태킹.
- **강 구역**: 물고기가 주기적으로 뛰어오름 — 존에 서 있으면 자동 포획. 큰 연어는 게이지형(낚시 느낌).
- **리스폰**: 채집 포인트별 재생성 쿨타임. 업그레이드로 단축.
- **희귀 재료**: 낮은 확률로 황금 재료 등장(반짝임 + 전용 사운드). 고급 메뉴 재료.
- **거리 = 가치**: 비싼 재료일수록 식당에서 먼 곳에 배치 → 동선 리스크/리턴 설계.
- (v0.1의 탭 미니게임은 폐기. 단, "황금 송어 출현 이벤트" 같은 시간제 이벤트로 손맛 요소 일부 계승 가능 — 후순위.)

### 4.4 손님(동물) 시스템 & AI
- **스폰**: 평판·식당 레벨에 따른 간격으로 입장. NavMesh로 이동.
- **흐름(FSM)**: `입장 → 줄서기(카운터) → 주문 표시(말풍선 아이콘) → 착석 → 식사 → 결제(테이블에 지폐 더미 떨굼) → 퇴장`.
- **인내심**: 대기 한계 초과 시 화내며 퇴장(말풍선 💢). 수익 손실만 — 평판 하락 같은 이중 페널티는 제거(스트레스 최소화, Cat Snack Bar 톤).
- **테이블 더럽힘**: 식사 후 접시/쓰레기 남김 → 치워야 다음 손님 착석(중반 해금되는 마이크로태스크, My Perfect Hotel 방식).
- 손님 종류는 식당 레벨로 해금. 고급 손님일수록 주문량·지불액↑, 인내심↓.

### 4.5 경제 시스템 (Economy)
- **재화**
  - **골드**: 손님이 바닥에 떨구는 지폐 더미를 **몸으로 주워서** 획득(자동 입금 아님 — 줍는 행위 자체가 보상 연출). 업그레이드·건설에 사용.
  - **보석(Gem)**: 하드 재화. 미션·광고·IAP로 획득. 시간 단축·치장에 사용.
  - **재료**: 채집으로 획득, 요리에 소비. (스택으로만 존재 — 별도 인벤토리 UI 없음)
- **업그레이드 비용 곡선 (지수형)** — v0.1과 동일 원칙 유지
```
다음_레벨_비용 = 기본비용 × (성장계수 ^ 현재레벨)   예) 100 × 1.15^Lv
수익 성장률(~1.07) < 비용 성장률(~1.15) → 새 확장 라인 해금 유도
```
- **의도된 병목 설계**: 일정 구간마다 "혼자서는 동선이 안 도는" 시점을 만들어 직원 고용·업그레이드의 가치를 체감시킨다.

### 4.6 업그레이드 & 확장 (Progression)
업그레이드는 패널이 아니라 **맵 위의 물리적 대상**에 직접 한다.
- **건설 존**: 잠긴 구역에 반투명 실루엣 + 필요 골드 표시. 돈 들고 서 있으면 카운트다운되며 지어짐.
- **스테이션 업그레이드**: 각 시설 옆 업그레이드 존(렌치 아이콘)에서 골드 투입 → 속도/용량/판매가 상승, **외형도 단계별 변화**(그릴이 커지고 번쩍해짐).
- **캐릭터 업그레이드** (유일한 메뉴 UI): 이동 속도 / 스택 용량 / 채집 속도.
- **직원 고용**: 고용 존에서 골드 투입. 직원별 역할 지정(채집/조리/서빙/계산). 직원도 속도·용량 업그레이드 가능.
- **식당 레벨**: 누적 매출 달성 시 레벨업 → 외형 대변신(노점→오두막→레스토랑) + 신메뉴·신손님 해금. 장기 목표의 시각화.

### 4.7 방치형 수익 (Idle Income)
- 직원이 배치된 스테이션만 오프라인 수익 발생: `GPS = Σ(자동화 스테이션 처리량 × 판매가 × 직원 효율)`.
- 오프라인 누적 상한 기본 4시간 → 업그레이드/광고로 8시간+.
- 재접속 정산 팝업 → 보상형 광고 2배.

## 6. UI / UX 설계

### 6.1 화면 구성
- **인게임(단일 화면)**: 3D 맵 + 플로팅 조이스틱. 상단 골드/보석 HUD, 식당 레벨 게이지. 좌측 미션 아이콘 1개, 우측 상점 아이콘 1개. **그 외 UI 없음** — 업그레이드·건설은 전부 월드 안의 존으로 처리.
- **캐릭터 업그레이드 패널**: 캐릭터 아이콘 탭 시 (속도/용량/채집 3종만).
- **상점**: 보석 IAP, 광고 제거, 치장(후속).
- **정산 팝업**: 오프라인 수익 + 광고 2배 버튼.

### 6.2 온보딩
텍스트 튜토리얼 없음. **바닥 화살표 + 반짝이는 존**으로만 유도: 강으로 안내 → 생선 3개 스택 → 그릴로 안내 → 요리 → 첫 손님 서빙 → 돈 줍기 → 첫 업그레이드 존 안내. (60초 이내 1바퀴)

### 6.3 UX 원칙
- 세로 한 손, 조작은 조이스틱뿐.
- **게이지는 벗어나도 리셋되지 않는다** (관대한 설계 = 장르 톤).
- 모든 행동에 즉각 피드백: 햅틱, 파티클, 코인 사운드, 출렁이는 스택.
- 카메라: 기울어진 탑뷰(약 45~55°), 식당 확장 시 줌아웃으로 성장 체감.

## 11. 기술 설계 (Technical Design — Unity)

> 2인 분담: **A = 게임플레이·경제·세이브·광고**, **B = UI/연출·콘텐츠 데이터·사운드** (섹션 13).

### 11.1 아키텍처 개요
- **데이터-드리븐**: 재료·메뉴·손님·스테이션·업그레이드 = ScriptableObject.
- **존 기반 인터랙션 코어**: 모든 시설은 `InteractionZone` 컴포넌트 변형 — 게임플레이 추가 = 존 프리팹 추가.
- **이벤트 기반 통신**: C# `event`/경량 이벤트 버스 (골드 변동 → HUD 갱신 등).

```
        ┌──────────────┐
        │ GameManager  │
        └──────┬───────┘
   ┌───────────┼──────────────┬───────────────┬──────────────┐
┌──┴────┐ ┌────┴─────┐ ┌──────┴──────┐ ┌──────┴─────┐ ┌─────┴─────┐
│Economy │ │Interaction│ │Agent        │ │Save        │ │Ads / UI   │
│Manager │ │ZoneSystem │ │(손님/직원AI) │ │Manager     │ │Manager    │
└────────┘ └──────────┘ └─────────────┘ └────────────┘ └───────────┘
    (A)        (A)            (A)             (A)        (A광고/B UI)
```

### 11.2 핵심 컴포넌트 설계 (v0.2 신규)
```csharp
// 플레이어: 조이스틱 이동 + 스택 보유
public class PlayerController : MonoBehaviour {
    // CharacterController 기반 이동, 플로팅 조이스틱 입력
}
public class StackHolder : MonoBehaviour {   // 플레이어·직원 공용
    public int capacity;
    public StackableType currentType;        // 한 번에 한 종류
    public void Push(Stackable item);        // 스프링 출렁임 연출 포함
    public Stackable Pop();
}

// 존: 모든 인터랙션의 베이스
public abstract class InteractionZone : MonoBehaviour {
    public float duration;                   // 0 = 즉시
    protected float progress;                // 벗어나도 유지(리셋 X)
    void OnTriggerStay(Collider c) { /* StackHolder 보유 에이전트면 진행 */ }
    protected abstract void OnComplete(StackHolder agent);
}
// 파생: GatherZone(채집), CookStation(조리), ServeZone(서빙),
//       CashierZone(계산), BuildZone(건설/업그레이드), TrashZone(치우기)

// 스테이션: 재료 투입 → 시간 → 완성품 대기열
public class CookStation : InteractionZone {
    public MenuData menu;
    public int queueCapacity;                // 완성품 보관 수
}
```

### 11.4 에이전트 AI (손님·직원)
- **이동**: Unity **NavMesh** (맵이 확장될 때 NavMeshSurface 재베이크 또는 사전 베이크된 전체 맵에서 구역만 개방).
- **손님 FSM**: `입장 → 줄서기 → 주문 → 착석 → 식사 → 결제(돈 프리팹 스폰) → 퇴장`. 인내심 타이머는 줄서기·주문 대기에만 적용.
- **직원 AI**: 역할별 단순 루프 — 예: 서빙 직원 = `픽업 존에 음식 있나? → 가져옴 → 주문 테이블로 → 반복`. 플레이어와 동일한 StackHolder·존 시스템을 사용하므로 별도 로직 최소화.
- **돈 더미**: 풀링된 지폐 프리팹 스택. 플레이어/계산직원 접촉 시 흡수 연출 후 골드 가산.

### 11.5 씬 구조
- `Bootstrap` (초기화·세이브 로드·SDK init) → `Main` 단일 3D 씬.
- 식당 확장은 씬 전환 없이 **같은 씬 내 구역 활성화**. 2호점(업데이트)은 별도 씬.

### 11.6 저장 / 불러오기
v0.1 설계 유지(JSON → persistentDataPath, 버전 필드, OnApplicationPause 저장). 저장 항목에 추가: 건설 완료 목록, 스테이션별 레벨, 직원 목록·역할, 캐릭터 스탯 레벨.

### 11.7 광고 SDK (Google AdMob)
v0.1 설계 유지: Bootstrap 초기화, 테스트 ID, 보상형 사전 로드 + graceful fallback, UMP/ATT 동의, `AdManager` 일원화.

| **M4. 콘텐츠·온보딩** | 1호점 풀 콘텐츠 | 전체 건설 트리, 메뉴 6종, 손님 6종, 화살표 온보딩 | 신규 유저 무설명 60초 1루프 |
| **M5. 아트·수익화** | 폴리시·광고 | 로우폴리 에셋 적용, AdMob, IAP | 비주얼 일관성, 광고/결제 정상 |
| **M6. 베타·밸런싱** | 외부 테스트 | 베타 빌드, KPI 수집 | D1 리텐션·진행 곡선 점검 |
| **M7. 출시** | 스토어 런칭 | .aab/IPA, 스토어 등록물 | 심사 통과 |

> **M1 강조**: 아케이드 아이들의 성패는 "이동+스태킹+돈줍기"의 촉감에서 90% 결정된다. 큐브와 캡슐만으로 1~2주 안에 검증하고, 재미없으면 수치(이동속도·스택 출렁임·코인 사운드)부터 튜닝한다.

## 13. 팀 역할 분담 (2인)

> Burger Please!도 2인 팀(개발 1 + PM 1)이 만들었다. 범위 관리가 곧 생존이다.

### 🅐 개발자 A — 게임플레이 & 시스템
- **개발**: 플레이어 컨트롤러·조이스틱, 존 시스템, 스태킹, 손님/직원 AI(NavMesh·FSM), 경제·건설, 세이브, AdMob, 빌드 파이프라인.
- **기획**: 경제 밸런스(비용 곡선·병목 설계), 동선/맵 레이아웃, 난이도 커브.

### 🅑 개발자 B — 연출/UI & 콘텐츠
- **개발**: HUD·팝업·상점 UI, 카메라(줌·연출), 파티클·햅틱·사운드, 스택 출렁임 등 juice 연출, 로컬라이제이션.
- **기획**: 콘텐츠 데이터(SO) 전체, 온보딩 화살표 흐름, 건설 순서 시나리오, 에셋 선정·톤 통일.

### 공동
- 코어 루프·맵 레이아웃·수익화 방향 공동 결정. 에셋 라이선스 시트 공동 관리.

## 14. 리스크 & 향후 과제

| 리스크 | 영향 | 대응 |
|--------|------|------|
| 조작감(이동·스태킹)이 밋밋함 | 장르 핵심 재미 부재 | M1에서 juice(출렁임·햅틱·사운드) 집중 튜닝, 레퍼런스 직접 플레이 비교 |
| 3D 전환에 따른 학습 비용 | 일정 지연 | 로우폴리+베이크드 라이팅으로 단순화, 에셋 적극 활용 |
| 동선이 단조로워지는 중후반 | 이탈 | 의도된 병목·신규 마이크로태스크(치우기 등) 순차 투입 |
| 경제 밸런스 붕괴 | 진행 정체 | 비용>수익 성장률 원칙, 스프레드시트 시뮬레이션 |
| 레드오션 장르 경쟁 | 노출 부족 | 고양이+직접 채집(타사에 없는 차별점) 강조, ASO/크리에이티브에 채집→스태킹 동선 노출 |
| 2인 작업량 과다 | 일정 지연 | 1호점만으로 출시, 2호점·치장·이벤트는 업데이트 |
| 광고/스토어 정책 | 출시 차질 | UMP/ATT 사전 구현 |

### 향후 확장 (출시 후)
2호점(강가)·3호점(설산), 치장(모자·앞치마), 일일 미션, 시간제 황금 송어 이벤트, 프레스티지(점포 매각), 시즌 한정 손님.

## 15. 부록 — 용어 & 레퍼런스

- **아케이드 아이들(Arcade Idle)**: 조이스틱 이동+스태킹의 아케이드 코어에 방치형 진행을 결합한 하이브리드 캐주얼 장르. 2020년 말 Homa Games가 개척, 장르 D1 리텐션 35~50%.
- **존(Zone)**: 캐릭터가 서 있으면 행동이 수행되는 바닥 영역. 본작 인터랙션의 기본 단위.
- **스태킹(Stacking)**: 아이템을 캐릭터 머리 위에 쌓아 운반하는 장르 핵심 메커니즘.
- **GPS / FSM / SO / 프레스티지**: v0.1과 동일.
